The task

Build a SQLite-compatible engine as a team

One main agent and eight DeepSeek workers worked through dsh-layerfs on the DeepSeek Harness at port 3080. Every file lived in the LayerFS project qv2-store/qv2-strata, on a Store on the Docker machine. Each bash call ran in a LayerFS Workspace: mount, run, commit, unmount. The run ended only when the SPEC's terminal pass held on a fresh fork of main.

How the team worked

  • 4 lanes (front end, VM, storage, tools), 2 workers each, plus a main agent who owned the shared contracts and integrated.
  • Each lane worked on its own Branch; the main agent merged lanes on an integration chain and published to main.
  • An operator session checked the run every 10–15 minutes (60 checks) and steered when it stalled.

What "done" meant (SPEC §9)

  • fmt, clippy with -D warnings, and cargo test all exit 0, with at least 1,500 tests.
  • Every corpus record matches SQLite 3.40.1's own answer.
  • All 16 acceptance checks, A01 to A16, pass against the reference sqlite3.
What was built

Strata: 15 crates, about 87,000 lines of Rust

A real b-tree pager with rollback and WAL journals, a SQLite-format schema, a shell that prints byte-for-byte what sqlite3 prints, and a 3,166-record corpus whose expected answers all come from SQLite itself.

Storage efficiency

30.2 TB of history in a 4.93 GB file

Every Commit records the whole project tree, about 9 GB of it, including build folders. LayerFS keeps each distinct piece of content once, then compresses and delta-encodes it. The whole run's history ended up smaller than a single checkout of the final tree.

任务

以团队方式构建一个兼容 SQLite 的数据库引擎

一个主智能体和八个 DeepSeek 工作智能体通过 dsh-layerfs，在 3080 端口的 DeepSeek Harness 上协作。所有文件都存放在 LayerFS 项目 qv2-store/qv2-strata 中，其 Store 位于 Docker 机器上。每次 bash 调用都在一个 LayerFS Workspace 中运行：挂载、执行、提交、卸载。只有当 SPEC 的终验在 main 的全新分叉上成立时，运行才算结束。

团队如何协作

  • 4 条泳道（前端、虚拟机、存储、工具），每条 2 个工作智能体；主智能体负责共享契约并进行集成。
  • 每条泳道在自己的 Branch 上工作；主智能体在集成链上合并各泳道，再发布到 main。
  • 一个操作员会话每 10–15 分钟检查一次运行（共 60 次），在运行停滞时进行引导。

“完成”的标准（SPEC §9）

  • fmt、带 -D warnings 的 clippy 和 cargo test 全部以 0 退出，且测试不少于 1,500 项。
  • 语料库中的每条记录都与 SQLite 3.40.1 自身给出的结果一致。
  • A01 至 A16 全部 16 项验收检查都对照参考 sqlite3 通过。

存储效率

4.93 GB 的文件保存了 30.2 TB 的历史

每次 Commit 都记录整个项目树，大约 9 GB，其中包括构建目录。LayerFS 对每份不同的内容只保存一次，再进行压缩和增量编码。整个运行的历史最终比最终代码树的一次检出还要小。

1,179×去重：30.2 TB 的树变为 25.6 GB 的不重复内容
5.4×压缩与增量编码：25.6 GB 变为 4.75 GB
约 6,100×总体：从保存的历史到磁盘上的字节
